## Install via pip

Install the Nova Act CLI with the `[cli]` extra to include all command-line dependencies:

```bash
pip install nova-act[cli]
```

<Note>
The `[cli]` extra includes all dependencies needed for the command-line interface. If you only need the Nova Act SDK for programmatic use, install without the extra: `pip install nova-act`
</Note>

## Verify Installation

Confirm the CLI is installed correctly:

```bash
act --version
```

You should see output similar to:

```
Nova Act CLI, version 1.0.0
```

## Check Help

View available commands:

```bash
act --help
```

View workflow-specific commands:

```bash
act workflow --help
```

## Verify Prerequisites

<Steps>
  <Step title="Check AWS CLI Configuration">
    Verify AWS credentials are configured:
    
    ```bash
    aws sts get-caller-identity
    ```
    
    Expected output:
    ```json
    {
        "UserId": "AIDAXXXXXXXXXXXXXXXXX",
        "Account": "123456789012",
        "Arn": "arn:aws:iam::123456789012:user/your-username"
    }
    ```
    
    <Note>
    If this fails, run `aws configure` to set up your credentials.
    </Note>
  </Step>

  <Step title="Check Docker">
    Ensure Docker is installed and running:
    
    ```bash
    docker --version
    ```
    
    Expected output:
    ```
    Docker version 24.0.0, build abc1234
    ```
    
    Test Docker is running:
    ```bash
    docker ps
    ```
    
    <Warning>
    If you see "Cannot connect to the Docker daemon", start Docker Desktop or the Docker service.
    </Warning>
  </Step>

  <Step title="Check Python Version">
    Verify Python 3.10 or higher is installed:
    
    ```bash
    python --version
    ```
    
    Expected output:
    ```
    Python 3.10.0 (or higher)
    ```
  </Step>
</Steps>

## Configure AWS Credentials

The CLI uses standard AWS credential resolution. Configure credentials using any of these methods:

<Tabs>
  <Tab title="AWS CLI">
    Configure credentials interactively:
    
    ```bash
    aws configure
    ```
    
    Provide:
    - AWS Access Key ID
    - AWS Secret Access Key
    - Default region (e.g., `us-east-1`)
    - Default output format (e.g., `json`)
  </Tab>

  <Tab title="Environment Variables">
    Set credentials via environment variables:
    
    ```bash
    export AWS_ACCESS_KEY_ID="your-access-key"
    export AWS_SECRET_ACCESS_KEY="your-secret-key"
    export AWS_DEFAULT_REGION="us-east-1"
    ```
  </Tab>

  <Tab title="AWS Profiles">
    Configure multiple profiles in `~/.aws/credentials`:
    
    ```ini
    [default]
    aws_access_key_id = YOUR_ACCESS_KEY
    aws_secret_access_key = YOUR_SECRET_KEY
    
    [development]
    aws_access_key_id = DEV_ACCESS_KEY
    aws_secret_access_key = DEV_SECRET_KEY
    ```
    
    Use a specific profile:
    ```bash
    act workflow --profile development deploy --name my-workflow
    ```
  </Tab>

  <Tab title="IAM Role (EC2/ECS)">
    If running on EC2 or ECS, the CLI automatically uses the instance/task IAM role.
    
    No configuration needed - credentials are retrieved automatically.
  </Tab>
</Tabs>

## AWS Permissions Required

The CLI requires specific IAM permissions. Choose the appropriate policy based on your use case:

## Region Support

<Warning>
**Important:** The AWS Nova Act service is currently only available in **us-east-1**.

While the CLI supports multi-region configuration, workflows must be deployed to us-east-1.
</Warning>
